Step 1: Test it

This prompt did the rounds on X this week, so I tried it on Opus 5.5 with nothing added to the prompt.

Paste this into Claude Code:

Make a dynamic 15-second motion graphics video that shows what an incredible motion designer you are. Go all out.

 

It picked up my brand colours by itself, because my Claude Code setup already knows them (yours will look different).

The clever bit is how. It writes the animation as code, draws every frame, then turns the frames into an MP4.

So you edit it by describing the change. "Slow down the second scene." "Swap the text for mine." "Make the orange navy."

Step 3: Build it

One line gets you surprisingly close.

Mine was a question everyone has asked and nobody can answer: why we dream. I picked it because we all want to know, and I knew AI could explain it visually. I typed this, word for word:

Why do we dream? And then someone suddenly wakes up, zooms out of the eye, and goes into outer space. There are neural networks of interconnectivity to convey the brain.

It found a source for every fact before it drew a thing, wrote the script as spoken lines, added an ElevenLabs voice and rendered it. Sound on:

 

Then I gave it notes, like I would a designer: "the text at the start undersells what’s coming next" and "you can’t really hear the audio on top of the sound effects". It fixed both.

Step 4: Build your brand design system

Mine came out in my colours because my setup already knows them. On a fresh Claude Code with nothing set up, the same line picks its own colours, its own type and its own idea of motion.

The fix is a brand design system. It’s one file of rules (your colours, type, timing and what never to do), and Claude reads it before it animates anything.

I built the one for my graphics the same way in How to quit AI slop. This is the motion version.

1. Build your design system from references. Put five frames from motion you already like in a folder called examples (screenshots from Dribbble or Pinterest are fine). Then paste this:

I am giving you five frames from motion graphics I already like. They are in the examples folder.

Write me one file called MOTION.md that any AI can read before it animates anything for me. It must cover:

1. Every colour as a hex code, and what each one is for
2. The fonts and the type sizes
3. Timing: how things come in, how long they hold, and how they leave
4. How things move: the frame rate, the easing, and anything that makes it feel handmade
5. Texture and finish
6. Five things my motion must never do, named plainly
7. One example, described shot by shot, of it done right

Work only from what is in the frames. Where you cannot tell, write ASK ME rather than guessing.

Show me the file before you save it.

I ran it on five frames from my own work. It pulled every colour as a hex code and wrote five things my motion must never do:

 

It also noticed I use four different looks, and it asked which one to use. I picked the deep blue glass.

2. Make Claude read it first. Paste this:

Add this to CLAUDE.md, and create the file if it does not exist:

Before designing, generating or animating anything, read MOTION.md in full.

Every colour, font, timing and motion value comes from that file.

The file sets the look, not the ambition. When I say go all out, go all out.

If something I ask for is not covered there, ask me rather than choosing for yourself.

When you have finished, check your own frames against MOTION.md, fix what fails, and only then show me.

4. Give notes like a designer. These are the notes I gave on my LinkedIn AI OS launch video, word for word:

"I wouldn’t say it looks very premium."

"This just isn’t in my brand colours."

"It needs a full stop at the end of ‘in your voice.’ It takes a while to get to the reveal."

"I hate the voice. Maybe we should just go for a nice backing soundtrack instead."

Each note names one thing to change and leaves the rest alone. The video is further down.

5. Add Apple’s motion rules. There’s a free skill that turns Apple’s design guidelines into rules Claude follows. Install it with one line:

npx skills add emilkowalski/skills --skill apple-design

Then I pointed it at the version with nothing set up and typed: “Use the apple-design skill to audit this animation. Give me a ranked list of everything that feels off, worst first.”

 

So “it feels a bit cheap” becomes a list of fixes. Then I switched the skill on and asked it to rebuild the Mac interface as a 20-second launch film:

 

The notch, the widgets and the wallpapers are all code. Claude drew every frame (and it still looks like a Mac).

6. Use real components. If your video shows a product, don’t let Claude draw the buttons and cards from scratch.

It guesses the spacing, and the UI looks fake (anyone who uses good software spots it in a second).

21st.dev publishes real components with a prompt under each one. I used it to build my website (step six of Claude Code built my website).

 

The same trick works for motion. Paste this once, then paste any component prompt straight in:

Add this rule to CLAUDE.md: whenever I paste a component prompt or third-party component code, treat it as a structural donor only. Keep its engineering. Replace its demo copy with my real copy, and translate every colour, border, shadow, font and timing to MOTION.md.
